Recap of last week:
- An LLM is a context completion engine, and the design of the context is important (refer to the role card exercise). Context = system instructions, knowledge base, and tools (introduced in this class).
- The user **modulates**, not controls the LLMs response based on the probability which the LLM is trained on, and can be fluctuated through the temperature setting.
---
Notes from this week's lecture:
- Knowledge = information YOU have provided, not purely from the model's trained context.
- RAG (retrieval augmented generation) = uses selection steps and semantic embedding to match vectors based on cosine similarity.

Helpful links to visualise concepts:
[LLM explorables](https://llmexplorables.aroughidea.com/)
[Embedding projector - visualization of high-dimensional data](https://projector.tensorflow.org/)

- Tools allow agents to perform other tasks besides generate text. It is a capability the model can call, and are registered separately from the instructions. Think of it as a small repository of the tools the LLM is able to utilise. The model has to be explicitly be trained to call the tool, meaning the more powerful a model is, the more likely it is able to use the tools reliably.
- A skill is NOT a tool, skills are simply types of system instructions (.md).

Links:
[Agent Design Studio - Tools Demo](https://agentstudio.aroughidea.com/w/tool-demo)
https://platform.claude.com/docs/en/claude_api_primer#tool-use

- Vibe coding is a mode of prototyping, where the user has an preliminary intent and creates dialogue with the agent to iterate through ideas. Intent can shift and/or change depending on the output.
- Vibe coding works via the LLM outputting code (through it's trained context) and directing it to a render tool that can visualise and execute the idea.
